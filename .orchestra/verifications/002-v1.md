## Findings

**F1 - NEW, non-blocking: the guard's "is this a full-tree collection?" test is
argument-based, so an invocation that NAMES the whole tree but EXCLUDES part of it is
treated as full-tree and the `gui` rule aborts the run.**

Root cause: `backend/tests/conftest.py:185-197` (`_is_full_tree_collection`) decides
"full tree" from the command-line arguments alone (`config.args`, or `testpaths` when
there are none). It does not look at `--ignore` / `--ignore-glob` / `collect_ignore`.
The `gui` rule's third clause (`:229-236`, "is registered as a live-GUI module but no
test was collected from it") then fires.

Measured on the branch:

| invocation | result |
|---|---|
| `python -m pytest backend/tests --ignore=backend/tests/acceptance --collect-only -q` | **exit 4** - "module 'acceptance/test_gui_fixture.py' is registered as a live-GUI module but no test was collected from it" |
| `python -m pytest backend/tests --ignore=backend/tests/acceptance/test_gui_fixture.py --collect-only -q` | **exit 4**, same message |
| `python -m pytest backend/tests --ignore=backend/tests/test_work_state.py --collect-only -q` (a module that is **not** registered) | exit **0** - the false positive is specific to the registered live-GUI module |
| `cd backend; python -m pytest tests -q --ignore=tests/acceptance` (the exact CI shape plus `--ignore`) | **exit 4** |
| `python -m pytest backend/tests -k "not acceptance" --collect-only -q` | exit **0** - `-k` deselects *after* collection, so the items exist and the guard is satisfied |
| `python -m pytest backend/tests --deselect backend/tests/acceptance/test_gui_fixture.py::test_invoke_flips_fixture_status --collect-only -q` | exit **0** - same reason |

Assessment: **no documented command uses `--ignore`** - not the Makefile (which uses
`-m "not acceptance"`, a deselection), not `ci.yml`, not the docs - so the pipeline and
every target in the Makefile are unaffected, and the failure is **loud** (exit 4), not
a silent lie. But a developer or agent who runs "the suite except the acceptance
directory" gets an abort whose message blames a module rather than saying "your
invocation excluded part of the tree". This is the plan's own named second risk ("a
false positive would break CI and every local run"), and it is a *new* failure mode
introduced by this item: before it, `--ignore` worked. Suggested fix (one of): treat
`--ignore`/`--ignore-glob`/`collect_ignore` as making the run partial; or derive
"full tree" from what was actually collected; or make the "no test was collected from
it" clause fire only when the module was not excluded by the invocation. **The
orchestrator owns `follow-ups.md`; I did not write it.**
