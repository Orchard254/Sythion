### N4 (new, non-blocking, diagnostic) - the 24-case matrix is **one** parameter set, so the loop aborts at the first failing case

The count contract (backend file 14 -> 15, collection 1642 -> 1643) forced the matrix into a single `pytest.mark.parametrize` parameter set with an inner `for` loop. The implementer disclosed this and the count contract is satisfied - but the consequence is that **one** failing case masks the rest of the matrix in the same run: a widening that breaks, say, `native / float` and `legacy-generate / list` reports only the first. The label in the assertion message does name the case that broke, so no information is lost about *which* case broke - only about the *other* cases that are also broken.

*Fix shape (optional, and it would move the count contract):* either aggregate the failures inside the loop (collect the mismatching labels and assert once on the list), or use 24 real parameter sets with `ids=[label for label, _, _ in _CANDIDATE_CASES]` and update the count contract to 38 / 1666. The coverage is identical either way; this is a diagnostics trade-off, not a defect. The implementer offered the second option in `reports/021-implement-3.md` §7.1, so the record is complete.
