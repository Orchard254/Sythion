## Findings (most important first)

1. `backend/tests/test_no_tautological_asserts.py:50-66` - **the detector is narrower than
   criterion 1's textual pattern.** `assert (x or True) and y`, `assert not (x or True)` and
   `assert x or (y or True)` are not flagged (I verified all three in a sandbox copy), although
   they contain the literal `or True` and would break criterion 1's `grep`. The plan's claim
   that the AST rule is "a superset of the literal `... or True` text pattern" is not true for
   nested positions. *Change (follow-up, not this item):* widen the rule to any `BoolOp(Or)`
   operand that is a direct child of an enclosing `BoolOp`/`UnaryOp` (but not of a `Call`), which
   catches the nested forms while keeping `assert f(x or y)` legitimate; or state the limitation
   in the module docstring so nobody treats the guard as a substitute for the textual check.
2. `backend/tests/test_no_tautological_asserts.py:50-66` - **the guard does not catch the most
   blatant tautology of all**: a bare `assert True` / `assert 1` / `assert "literal"` (verified:
   not flagged). The item's stated purpose is "assertions that can never fail", and `assert True`
   is the canonical example. *Change (follow-up):* extend the rule to flag an assert whose whole
   test is a truthy constant.
3. `backend/tests/test_phase105_concurrency.py:536-545` - **the ownership assertion is a canary,
   not a contamination detector**: `event_history()` filters on `task_id` in SQL
   (`backend/runtime/events.py:75-79`), so the property is guaranteed by today's implementation;
   the assertion can only fail on a query/projection regression. It also cannot detect the
   reverse contamination (an event intended for `tid1` stored under `tid2`), because the test
   writes `{"i": i}` payloads with no task marker. The assertion as written matches its own
   comment, so this is not a defect - but the comment could be tightened so a future reader does
   not over-claim. *Change (optional):* write a per-thread marker into the event payload so the
   test can detect cross-thread contamination as well; that changes the test's write pattern and
   is not needed for this item.
4. `backend/tests/test_phase1075_hardening.py:769-777` - **site 3 was never executed** (gated on
   `SYTHION_RUN_PROVIDER_E2E=1`); I verified the assertions statically against both artifact
   branches (`_normalize` and `_fallback_artifact`) instead of by running them. Honest gap, no
   action available in this item.
5. `backend/tests/test_phase125_planning_validation.py:232` - `assert q["details"]` is a
   **behavioural** assertion, not only a shape one: it now couples the test to the selector's
   learned policy (five recorded `DEPENDENCY_AWARE_PLAN` successes must keep it from diverging
   from `DEPENDENCY_AWARE_PLAN`). That is the intended non-vacuity check and it is deterministic,
