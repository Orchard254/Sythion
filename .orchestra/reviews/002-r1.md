## Guard assessment

The guard is `backend/tests/conftest.py`: classification in `pytest_itemcollected` (the right
hook - pytest's `MarkPlugin.deselect_by_mark` is `tryfirst`, so a marker added in
`pytest_collection_modifyitems` would be invisible to `-m`; the reasoning is written into the
code and I confirmed the mechanism works by measurement, not by reading), verification in
`pytest_collection_finish`.

**Teeth - confirmed.** The guard aborts a full-tree collection with `pytest.UsageError` /
exit 4 on drift. I exercised it four ways:

| Probe | Result |
|---|---|
| clean tree, full-tree collection | 1609 collected, **EXIT=0** (guard silent) |
| a second module with `pytestmark = pytest.mark.gui` (a **legitimate** future change) | **EXIT=4**, `ERROR: selection-contract violation in the backend test tree: - marker 'gui' is applied to 1 test(s) it does not describe, e.g. backend/tests/acceptance/test_gui_extra.py::test_extra_gui_probe` |

| repo-root `pytest.ini` removed | **EXIT=4**, zero tests run: `- no pytest configuration file was used; expected pytest.ini at the repository root` + `- the root configuration does not declare the marker(s): acceptance, concurrency, flaky, gated_soak, gui, ...` |

**Partial runs are not affected - confirmed.** `pytest backend/tests/test_work_state.py
--collect-only` -> 57 collected, **EXIT=0**; `pytest backend/tests/acceptance --collect-only`
-> 193, EXIT=0. `_is_full_tree_collection` matches only the `backend/tests` root (or, with no
path arguments, the configured `testpaths`), so a single file, a single directory or a
single node id never trips it.

builtins), and a full-tree collection aborts with exit 4 and runs **zero** tests. So the
comment that promises the suite "still runs" in that state is false, and the fallback's only
observable effect is on partial runs inside `backend/tests`. See finding 2.

## Findings (most important first)

1. **`pytest.ini:33` (and the header claims at `pytest.ini:3-5` and `:16-18`) - the
   `gated_soak` description is false.** It says "long-running soak tests, gated behind an
   explicit environment flag", but the only test carrying the marker,
   `backend/tests/test_phase115_soak.py::test_learning_soak_mixed_workload`, has no

   every default suite run - `pytest backend/tests/test_phase115_soak.py -q` -> **1
   passed**. This is precisely the failure the item exists to remove: the file calls itself
   "the single source of truth ... what each marker actually selects", and a future agent
   reading it will believe the soak test does not run by default. The header's claim that
   "the marker populations are enforced by the selection-contract guard" is also too broad -
   the guard checks only `acceptance`, `gui` and `network`, so nothing would have caught
   this. **Fix:** reword to what is true (e.g. "the long-running learning soak test;
   NOT gated by an environment flag - it runs in the default suite
   (backend/tests/test_phase115_soak.py)"), and narrow the header sentence to the three
   populations the guard actually enforces (or extend the guard).

2. **`backend/tests/conftest.py:32-35` - the fallback comment promises something the guard
   prevents.** It says the declarations below are "only a fallback, so the suite still runs
   ... when it is run without that file". Measured with the root `pytest.ini` removed

   canonical markers, because the fallback lives in a conftest that is only loaded when the
   tree is collected. The fallback's real (much narrower) effect is: markers are declared
   for a *partial* run inside `backend/tests`. **Fix:** either make guard rule 5 tolerate an
   absent root configuration (then the fallback really does keep the suite runnable), or
   delete the fallback block and rewrite the comment to say the suite refuses to run without
   the repository-root `pytest.ini`. Either way the comment must match the behaviour. This
   cannot bite the merged tree (the ini is committed) or CI, but it is a false statement in
