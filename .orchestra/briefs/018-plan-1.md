# Brief: plan - 018 - attempt 1

- Item: 018 The vault-write guard must not be swallowed by the FastAPI global exception handler (R-026)
- Role: planner
- Goal: Sythion's "better" includes honest safety guarantees. Item 007 shipped a
  guard that blocks any test from writing to the product's real credential target,
  by raising `ProductCredentialWriteAttempt` before the `win32cred` call. But
  `backend/main.py`'s `@app.exception_handler(Exception)` converts every unhandled
  exception into a 500. A test that drove a vault write through `backend.main.app`
  would see a 500 indistinguishable from any other fault: the write would still be
  blocked, but the test would NOT go red - the guard would silently degrade from a
  check into a circuit-breaker. Your plan must close that hole and prove it.
